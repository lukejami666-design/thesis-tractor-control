# 第三章起步混合自动机监督门控：封存实现说明（2026-11-14）

本文描述实际封存的候选 J 代码及其缺陷，供论文方法与局限性写作参考。工程检查未通过，未移植至正式 tractor_mu，不能称最终部署控制器。控制代码以 `src/LaunchTCS_Motion.m`、`src/MONITOR_gate.txt`、`src/LaunchTCS_Torque_gate.m` 和 `src/launch_state_actual.txt` 为准，所有取值以 `data/candidate_J_full_parameters.mat` 为准。

## 1. 对象、工况与信号

四轮顺序为 FL/FR/RL/RR。轮端半径 `[0.834,0.834,0.94,0.94] m`；车轮相对质心 x=`[2.043,2.043,-1.362,-1.362] m`，y=`[1.195,-1.195,1.165,-1.165] m`。控制采样周期 0.001 s。

研究的是低速有载起步的事件监督与轮端命令约束。外部阻力经第 2 轴等效外力接口输入；车辆求解器当前采用常摩擦道路与轮胎力表，不能未经验证命名为软土牵引模型。油门0.5、0.8及0→0.8/1 s斜坡与 L0/L1/L2 构成历史九工况。

Motion 对轮速、vx/vy、ax、r 作一阶滤波；轮速输入为 rad/s，转角为 rad。每轮参考速度：

`v_ref_i=max(0,(vx_f-r_f*y_i)*cos(delta_i)+(vy_f+r_f*x_i)*sin(delta_i))`。

`dv_i=max(omega_f_i,0)*R_i-v_ref_i`（m/s）；其额外 5 ms 滤波后取非负得到 dv_ctrl，差分得到 dv_rate_ctrl。dv 是轮面与轮向地速之差，避免直接以低速滑转率作为启动闭环误差。

`lambda_raw` 是已有“滑转率计算”子系统的四轮未滤波比值，模型块实际为 `(Roll_i-vwx_i)/max(Roll_i,vwx_i,0.1 m/s)`。其轮向速度计算路径与 Motion 的滤波 v_ref 不同，不能把两者混为完全相同的原始量。低速分母虽有 0.1 m/s 下界，近零速比值仍对微小轮速敏感。它用于原口径的结果描述和旧工作路径，不是本起步门控的 P/I 反馈误差。求解器原始 Kappa_L1i 等另保存在 `solver_export_raw` 中，也不能不加区分地替换为 lambda_raw。

T0 是总需求；T_base 是基础分配经共同能力限制与 Memory 后的四轮需求；T_max 是当拍可用能力；T_target 是单轮约束后的目标；T_cmd/T_actual 是发往车辆的命令。没有电机实测扭矩传感数据。`slip_ratio_out` 是遗留的 bound/base 比例诊断，不是物理滑转率。

## 2. MONITOR 与混合自动机

Motion 只计算瞬时量，不计时、不锁存。有效驱动需已施加命令达到 `0.02*T_max`；持续空转瞬时条件需 dv_ctrl>0.8 m/s、轮面速度>0.3 m/s、有效驱动和源健康。持续高滑转不要求 dv 继续增长。快恶化另需 dv_ctrl>0.65 m/s 且增长率>3 m/s²。

MONITOR 每 1 ms 先更新源健康，再更新确认/清除计时器、预警计时器、未起动判据、车速有效性，最后决定 desired_stage。

预警的普通入口为 dv_ctrl≥0.50 m/s 持续10 ms；提前入口为 dv_ctrl≥0.35 m/s 且快恶化持续5 ms。warn_armed 防止高 dv 期间重复进入。预警最短保持120 ms，低于0.25 m/s持续60 ms后清除；确认空转或源故障立即接管/取消预警。预警不阻止持续空转确认。空转确认累计80 ms，dv_ctrl<0.4 m/s持续250 ms清除。

源即时异常（非有限运动量、无效速度源或不可置信地速等）直接 source_bad；速度差分与加速度不一致累计200 ms也可触发故障。故障优先于多轮、单轮、有效速度及未起动判据。

|状态|名称|实际含义|
|---|---|---|
|255|DISABLED|禁用；reset 清计时/记忆|
|0|START_PROBE|尚无已确认运动/空转，当前正常需求通道|
|1|NORMAL_LAUNCH|已有运动证据|
|2|HEAVY_NO_MOVE|有效驱动但未起动证据持续0.8 s|
|3|SINGLE_SPIN|一轮确认空转|
|4|MULTI_SPIN|至少两轮确认空转|
|5|WORK_PASS|车速有效判据及故障/空转条件允许后的监督状态|
|6|PROTECT|源故障优先保护|

车速有效入口 vx_f≥1.5 m/s 持续150 ms且最多一轮空转，退出阈值1 m/s、100 ms，至少两轮空转/源故障也使其退出。状态3/4在实际转移图中有 `after(0.2,sec)` 的退出保持，故障和禁用不等该保持；不可把 P 中遗留的0.15 s参数写成这张图实际使用的保持时间。

## 3. Torque 实际实现

本实现不运行起步 P/I 或 fast-P 修正，相关增益置零，I_dv/cut_f 等为接口兼容。rate 以固定额定轮端能力 `[34936,34936,72408.24,72408.24] N·m` 归一化，不以移动的 T_max 作速率基准。

无预警/确认时，除状态2外 envelope 直接跟随 `min(T_base,T_max)`；状态2按1/s额定轮端扭矩缓升。预警或确认保持期间 envelope 保留事件前值，构成阻止继续增扭的约束。不能再写成状态0/1的 envelope 从零缓慢探测至需求。

预警或确认上升沿一次性锚定 `anchor=max(T_actual_prev,min(T_base,T_max))`。预警目标为 `max(T_actual_prev,0.9*anchor)`；预警龄期≥35 ms且继续恶化/达到空转阈值时，bound以1/s向该目标下降。确认目标为 `0.75*T_actual_prev`，bound按2/s下降，绝对下界0 N·m；清除后按0.5/s恢复。

**上述是代码分支的定义，不代表实际已经达到目标。** 当前 bound 初始化1e12且没有在事件沿有限化，5 s内始终不构成单轮限制；这是实际缺陷。本轮保持原实现留档，不把论文写成已验证的单轮0.75倍限扭。

至少两轮确认时，multi_anchor取已施加总命令；multi_bound按总额定能力1/s下降至0.95*multi_anchor，清除后0.5/s恢复。对多轮上界只做总量交集，不把各轮惩罚重复相乘。重分配系数0，未启用轮间转移。

每轮先交 envelope、单轮上界、基础需求、能力及保护限幅，得到目标；命令以24/s上升、6/s下降。变化率限制后，按多轮总硬界同比例投影，再按逐轮硬界裁剪；保护对每轮再要求≤0.1*T_max，最终公共能力块再次保证命令非负且不超当拍能力。安全覆盖允许突破普通下降速率，覆盖标志/数量记录在 gate_diag65–72。

gate_diag1–4 envelope，5–8 bound，9–12 anchor，13–16 prewarn，17–20 spin，21–36各类限制标志，37–40 reason，41–44 handed_off，45–48 transfer，49–52 protect，53–56 target诊断，57–60恢复标志，61–64 multi_bound，65–68安全覆盖标志，69–72覆盖量。**53–56存在重复RR标量的记录错误，真实逐轮目标应从 T_target 与 T_lim_out 取得。**

## 4. 一个控制周期与交接

实际信号依赖顺序为：车辆/传感输出与上一拍命令反馈 → 量纲转换、Motion滤波和瞬时判据 → 并行监督区域 MONITOR 更新 desired_stage → MODE 区域状态转移并给出 stage → Torque事件边沿、记忆、目标和速率 → 多轮/逐轮安全投影 → 分支选择与共同电机能力钳位 → 车辆输入；Memory 给下一拍提供反馈。基础垂载分配也经自己的能力限幅和一拍 Memory 形成 T_base。具体状态结构与转移标签已从实际 Chart 导出，不按早期示意图推断。

需要区分两种交接：Chart 的状态5由 speed_valid 及空转/故障优先级决定；Torque 内部在 vx_raw≥2 km/h保持20 ms后锁存 handed_off，按0.7/s恢复包络和上界，返回近静止且stage≤1才重新允许起步监督。J在0.425 s已内部交接，但整个5 s Chart仍在状态4。该行为必须作为适用边界/待修复项，不写成“状态5已接管”。

## 6. 与垂载基线的共同/不同路径

共同路径：同一总需求映射、垂载分配、能力图、外力、求解器、初始条件和记录窗口。真实 T_base 已带上游能力钳位；末级能力块在两分支共享。油门0.8本身不等于输出扭矩恒定。

不同路径：基线选择旁路，公共能力块前命令直接来自 T_base；门控选择 Torque 命令，经过事件包络、上界、速率和安全投影。基线后台仍可计算 stage/prewarn/spin，但未执行该控制路径；不能据此说垂载基线也在状态4主动执行多轮门控。

## 7. 验证范围与结论边界

第一轮约束修正版留有完整九工况矩阵，候选 J 只有五个工况的历史数据。本轮仅固定复跑 L2_U08两分支及隔离保护回放。不同版本严格按 `validation_version_index.csv` 区分。

J：t2=0.406 s，真正垂载基线0.407 s；共同窗口dv降低约2.9%，λP95降低约0.107%，均不达既定目标。单轮bound失效、诊断目标向量错误及状态/执行器交接不一致，使其不能通过工程部署门槛。牵引收益结论为“证据不足”；当前数据不能证明物理平台，也不能证明进一步防滑优化物理不可行。

本稿应作为方法实现审查和失败原因记录使用。后续修改应先处理被本轮证据定位的实现缺陷，再建立清晰的新旧版本对照；不将本候选写为已完成优化的最终控制器。
